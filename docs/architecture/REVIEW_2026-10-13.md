## Diagram semantics reviewed

- V1: Direction LENT vs BORROWED, OPEN-only balance, partial repayment vs confirmed settlement, zero-net/open safety, Room entity relations, logical activity transaction reference, app-private sandbox and SAF crossings.
- V2: Consent before agreed debt; pending versus confirmed financial effect; counterparty-confirmed repayment; accepted financial history separate from rejected/disputed outcome log; native local V1 data never automatically uploaded.
- Sync: durable outbox, same-operation retry, lost response after commit, payload fingerprint mismatch, atomic version/precondition check, sanitized read results, reconciliation before resolving an outbox item.
- Trust: independent authentication, per-object read/write authorization, consent, valid money/state, denial/rejection paths, guarded shared-data export/revocation/deletion.

## Publication checks and outstanding cautions

1. Structural readback used editor page shape IDs, arrow terminal bindings and bounding-box intersections. This does not prove every rendered connector avoids text or that individual labels never overflow.
2. Page 06 and Page 10 retain a few central arrow crossings; remain readable as design-review diagrams but can receive another visual-polish pass.
3. SVGs were produced through editor.getSvgString. ForeignObject-based text and embedded styles may render differently across GitHub, browsers and PDF converters; verify in the intended target viewer.
4. Existing docs are source snapshots, not executed runtime or concurrency proofs. Reconcile with the latest Git SHA when Phase 3 begins.
5. V2 provider/crypto selection, operation IDs, financial event and money schemas, conflict policy and legal/privacy lifecycle decisions are still open.
6. Board-level native snapshot uses editor.getSnapshot().document with null session; validate editor.loadSnapshot in a scratch board before depending on it for disaster recovery.
